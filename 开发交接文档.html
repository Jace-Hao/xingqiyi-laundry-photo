01

项目速览

  • 定位：洗衣门店「衣物拍照存档」桌面系统 —— 扫码建档、最大分辨率拍照、拍摄时间水印烧录、多机联网协同、照片查询与导出。
  • 技术栈：Electron 33 + Vue 3（渲染层为单文件应用），运行时零第三方依赖；打包 NSIS（Windows x64）。
  • 仓库与发布：https://github.com/Jace-Hao/xingqiyi-laundry-photo —— 对外发布走 GitHub Releases；下载页为 docs/index.html（发布页）。
  • 当前版本：v1.1.10（2026-09-24）。本机 dist 目录仅保留 1.1.8 ~ 1.1.10 安装包（09-24 整理后）；历史版本见 GitHub Releases（v0.1.8 起）。
  • 质量基线：npm run verify 共 9 个脚本、384 项断言全绿；界面截图流水线与行为测试见第七章。

核心机制（维护向）

双模式运行、数据位置、拍照水印、缩略图缓存、离线补传、四级权限等基础机制详见 README 与项目总览页；以下是维护者最需要知道的重点。

更新链路（v1.1.4 起）

  1. 检查更新：api.github.com 直连失败/超时后，自动经 gh-proxy.com 镜像重试（整体 24 秒超时兜底）。
  2. 下载安装包（main/update-download.js）：候选链为「直连 → 三个国内加速通道（gh-proxy.com / ghproxy.net / gh.ddlc.top）」。连接失败、15 秒断流、首段速度过慢均自动切换下一通道；下载进度会标注当前通道（直连 / 国内加速），完成提示注明是否走了加速；取消立即生效且不会继续切换通道。
  3. 备用与内网分发：统一使用软件安装目录下的「软件更新」文件夹（历史位置：系统下载目录、%APPDATA%\updates，应用启动时会自动搬迁）；启动与「检查更新」会扫描该文件夹并提示。
  4. 强制推送：服务端管理员选包开启后，客户端下次登录静默下载（内网地址直连下载，不走加速）。
  5. 维护：加速镜像失效时改 main/main.js 顶部的 GH_ACCEL 列表即可；接口加速前缀为 GH_ACCEL_API（当前仅 gh-proxy.com 支持代理 api.github.com）。

安装更新自保护（v1.1.6 起）

  • 问题背景：安装包存放在 安装目录\软件更新\ 内，electron-builder 默认的「关闭正在运行的应用」按 $INSTDIR 路径前缀匹配进程，会把安装器自己一并匹配——温和阶段发 WM_CLOSE 直接关掉向导，强制阶段直接结束自身进程；且旧版（≤v1.1.5）卸载器同款逻辑会在升级时把新安装器一起杀掉（旧文件被卸、新文件未装）。
  • 修复①（build/installer.nsh，electron-builder 自动拾取）：customCheckAppRunning 改为按进程名精确 tasklist/taskkill（只针对应用，不碰安装器/卸载器）；温和关闭失败再逐级 /F /T 强杀；仍失败弹重试对话框。
  • 修复②（同文件 customInit）：从「…\软件更新」目录内启动安装器时，先复制自身到 %TEMP%（保留原文件名）再从那里重启，脱离旧卸载器的路径匹配范围。
  • 修复③（main/main.js）：关闭事件检测到「{包名}-setup*」或「Uninstall {产品名}*」进程时真正退出（不再隐藏托盘）；「立即安装」启动安装器后轮询监视，检测到安装器进程即自动退出让位（startUpdaterCoExitWatcher）。
  • 验证：隔离测试副本（改名构建）跑「旧版运行中 + 升级安装」与「新版运行中 + 重装」两场景，全流程到完成页、无孤儿临时目录、无自杀。

查询页分页与当日订单表格（v1.1.7 ~ v1.1.10）

  • 查询页分页器：上一页/下一页之间有页码下拉（goPage + .pager-select），选项「当前页/总页数」，越界自动收敛；仅 QueryPage，管理端日志页分页器未动。
  • 「⬇ 下载当日订单」按钮（筛选栏「重置」旁，任何筛选状态可见——批量栏在列表为空时会隐藏）：一键导出今天录入的全部订单，只生成表格不复制照片（v1.1.9 原为完整导出，v1.1.10 按反馈改为仅表格，供洗衣管家上传助手同步照片使用）。
  • 实现：exportPhotosByDate 带 tableOnly 参数——CSV 列 = 条码 / 已存档张数 / 照片在本系统的实际存放文件夹（服务端按 photoDir 实路径；客户端写服务端相对目录）；旧版服务端无此模式时渲染层自动回退完整导出；确认框与 toast 明确「不含照片」。
  • 测试：exporttoday-test.js（stub 覆写 confirm 与选目录，断言按钮存在 / 确认框含今日日期 / 成功 toast / 可重复触发）；截图识图确认上屏排版。

输入法组合态防护（v1.1.8 起）

  • 所有 window 级 keydown 处理器（拍照页 onKeydown、查询页灯箱 onKeydown）开头必须放行输入法组合态：if (e.isComposing || e.keyCode === 229) return;。
  • 否则中文输入法按回车确认候选词会被 preventDefault 强杀组合并失焦，表现为「输入内容删除后无法再次输入」。
  • 新增任何键盘快捷键时照抄这一行；测试见 capture-input-test.js 场景 D（keyCode 229 模拟，修复前 FAIL / 修复后 PASS）。

摄像头按需占用（v1.1.3 起）

  • 拍照页空闲 3 分钟自动休眠并释放摄像头；窗口最小化/隐藏立即释放；回到前台自动恢复；
  • 唤醒方式：扫码、按空格、点击「唤醒拍摄」按钮；另有「释放摄像头」手动按钮；
  • 实现位于 renderer.js 的 CapturePage 组件（常量 CAM_IDLE_DEFAULT_MS 可调，测试可用 window.__xqyCamIdleMs 覆盖）。

图标与快捷方式

  • 安装包与桌面快捷方式图标同源：win.icon = renderer/assets/logo.png（500×500，源文件 logo.svg）；
  • 换图标后如系统仍显示旧图标：重启「Windows 资源管理器」或运行 ie4uinit.exe -show；任务栏钉住的需取消后重新钉。

构建与发布流程

  1. 升版本号：package.json → README（3 处）→ docs/manual.md（4 处）→ CHANGELOG（新段）→ renderer.js 中的示例文件名；发布页版本串在第 3 步统一改。
  2. 构建（可能遇到 GitHub 网络抖动，需下载 Electron 运行时）。推荐带镜像：
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
$env:ELECTRON_BUILDER_BINARIES_MIRROR = 'https://npmmirror.com/mirrors/electron-builder-binaries/'
npm run build
  1. 发布页同步：以 开发工具\发布与补丁\patch-docs-*.js 最新版本号为模板（现有 116~119+110，升版时滚动复制一份改参数）（从构建产物实读大小/SHA 回填，带命中数断言与残留检查）。
  2. 提交与推送：git add 指定文件 → commit → push（GitHub 直连不稳，建议脚本化重试）→ 打 tag 并推送。
  3. 发布 Release：以 开发工具\发布与补丁\github-release-*.ps1 最新版本号为模板（现有 116~119+110；改顶部 tag / 文件名即可）。脚本自动：组装发布说明（CHANGELOG 段 + SHA256）→ 建草稿 → 上传 blockmap + exe → 转正式 → 带凭据与匿名双路复核。
  4. 终检：匿名访问 releases/latest 应指向新版本；直链与三个加速通道抽查（HTTP 200/206）。

注意：不要修改已发布版本的资产；一切新内容走「版本号升级 + 新 Release」。

本机环境与注意事项（踩坑清单）

  • 换行符：部分文件在历史 rebase 后为 CRLF —— 编写补丁脚本要用「行尾自适应」（按文件实际 CRLF/LF 匹配与回写），否则会命中失败或产生整文件 diff。
  • 临时区易失：.openclaw\tmp（E:\软件开发 与 E:\autoclaw 两处）会被外部清理（2026-09-22 已发生）——重要产物及时落进项目内或提交入库，不要长期放临时区。
  • GitHub 网络：push、构建、发布都可能需要重试；构建用 npmmirror 镜像最稳；git 凭据经 git credential fill 读取（不落盘）。
  • 更新文件夹：位于软件安装目录下「软件更新」，卸载软件会连同清理——需要长期留存的安装包请另存。
  • 安装器自我追杀陷阱：安装包放在安装目录内 + electron-builder 默认关闭逻辑按路径前缀匹配 → 升级时新安装器/旧卸载器会杀掉自己或对方（v1.1.6 已修，详见 §四「安装更新自保护」）；以后若改动更新目录名或关闭逻辑，务必重跑隔离升级验证。
  • 端口：服务端默认 17521，被占用时在设置中修改。
  • 本机可能同时承担门店日常使用（有常驻业务软件）——涉及系统级操作（重启资源管理器、安装/覆盖软件）请避开营业时段。
  • 输入法组合态：所有 keydown 快捷键必须带 isComposing || keyCode===229 防护（v1.1.8 教训：中文输入法回车确认候选被拦截 → 删除内容后无法再次输入）；合成事件测试全过 ≠ 真实键盘没问题，输入类报障优先查 IME 路径。
  • 测试窗口弹在门店机上会被人顺手点击（2026-09-24 实际发生，导致向导被人为推进）：自动化向导测试要把按钮点击做全（「安装(&I)」这类文本会误中单选按钮文案），测试尽量短、即测即清。
  • 文档习惯：中文、全角标点；提交信息沿用 feat / fix / chore / release: ... 前缀风格。
