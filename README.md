# 星期衣精致洗衣衣物照片系统

基于 **Electron + Vue 3** 的洗衣店衣物拍照存档桌面应用，支持**多台电脑联网使用**：衣物按条形码建档，以摄像头最大分辨率拍照留档；管理端可管理账号权限、审计操作日志、查看全部数据并自定义照片保存路径。

**当前版本**：v1.1.4（2026-09-22）· [更新日志](CHANGELOG.md)

## 一、快速开始

### 1. 一键安装（推荐，终端电脑使用）

1. 双击 `dist` 目录中的安装包 `xingqiyi-laundry-photo-setup-1.1.4.exe`
2. 若出现「已保护你的电脑」提示，点「更多信息」→「仍要运行」
3. 按安装向导完成安装：可自选安装目录（默认为当前用户程序目录），完成后桌面生成快捷方式，双击即可使用

安装包已内置全部运行环境，目标电脑**无需安装 Node.js 或任何依赖**。

### 2. 源码运行（开发者）

```bash
npm install   # Electron 下载慢时先执行：$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
npm start
npm run build # 重新打包安装包
```

### 3. 首次启动：选择运行模式

首次启动会进入「运行模式设置」页，二选一：

- **作为服务端**：本电脑作为数据中枢，账号、存档、日志、照片全部保存在本机，并开启局域网服务（默认端口 17521）。保存后重启应用生效。
- **作为客户端**：本电脑作为工作站，连接已有服务端。填写服务端管理员提供的**服务器地址**（如 `http://192.168.1.10:17521`）与**连接码**，可先点「测试连接」验证。

> 之后想切换模式或查看连接信息，用管理员账号登录管理端的「系统设置」页即可。

### 4. 默认账号

| 账号 | 密码 | 角色 |
| ---- | ---- | ---- |
| admin | admin123 | 系统管理员（管理端） |

**首次登录后请立即修改密码**。

## 二、软件激活

安装后首次使用需输入**激活码**完成激活，未激活可试用 **7 天**。

- 登录页「软件激活」弹窗显示本机**机器码**（16 位，每台电脑唯一），激活码与机器码一一绑定
- 试用到期后强制要求激活，无法继续使用
- 管理员使用「激活码计算工具」（`scripts/license-tool.js`）根据客户机器码生成激活码

```bash
node scripts/license-tool.js <机器码>   # 生成激活码
node scripts/license-tool.js --verify <机器码> <激活码>  # 校验激活码
```

## 三、多电脑联网说明

### 同一局域网

服务端启动后，管理端「系统设置」页会显示**本机局域网 IP、端口、连接码**。其他电脑安装本软件后选择「作为客户端」，填入 `http://局域网IP:端口` 与连接码即可，数据实时读写服务器，无需手工同步。

**其他电脑连不上？按顺序排查：**

1. **防火墙放行（最常见原因）**：服务端电脑的 Windows 防火墙默认拦截入站连接。在服务端电脑上，右键「开始」菜单→「终端（管理员）」，执行以下命令放行端口（端口号按实际修改，默认 17521）：

   ```powershell
   netsh advfirewall firewall add rule name="星期衣衣物照片系统" dir=in action=allow protocol=TCP localport=17521
   ```

   也可以在管理端「系统设置」页点击「复制防火墙放行命令」一键复制。首次启动时若弹出防火墙授权窗口，务必勾选「专用网络」并点「允许访问」。

2. **确认服务端在线**：服务端应用必须保持运行（服务随应用启动，关闭应用窗口即停止服务）。
3. **确认同一局域网**：客户端与服务端需连接同一台路由器/交换机；在客户端电脑 `ping 服务端IP` 应能通。
4. **地址与连接码**：客户端填写的地址须为 `http://服务端IP:端口`，连接码以服务端「系统设置」页显示的为准（重置后需重新配置）。

### 跨城市 / 异地使用

数据全部集中在服务端，天然无需同步文件。跨网段打通网络推荐两种方式：

1. **异地组网（推荐）**：在服务端与每台客户端电脑安装虚拟局域网工具（如 Tailscale、ZeroTier），各设备会获得同一虚拟网段内的固定 IP，客户端填写该虚拟 IP 即可，安全性好、配置简单。
2. **内网穿透**：使用花生壳、frp 等工具，把服务端端口映射到公网地址，客户端填写映射后的地址。注意连接码务必保密，映射端口相当于把服务暴露到公网。

### 安全设计

- 客户端与服务端间所有请求必须携带**连接码**，错误连接码直接拒绝
- 登录采用**会话令牌**机制，**同一账号唯一登录**：不可同时在多地登录，异地登录会使原会话立即失效并退回登录页，提示中写明顶下线的登录时间与来源 IP；账号停用/删除后其所有会话立即失效
- **离线登录不受唯一登录限制**：服务器失联时客户端用本机镜像登录，不经服务端签发会话，因此不会被顶下线；离线数据在重新登录后仍会补传，即使该账号此时已在别处登录
- 密码使用 scrypt 加盐哈希存储；客户端可查看本人及**同门店**账号的存档（未分配门店的账号仅可见本人存档）
- 连接码可在「系统设置」中随时重置

### 门店分组与四级角色

**门店分组**：账号可归属门店，同一门店的账号可互相查询订单照片；订单保存录入时的门店快照，账号调店后历史订单仍归原门店。门店名必须完全一致才算同店；**未分配门店的账号之间不互见**（避免空值相等导致互相看到全部数据）。

| 角色 | 拍照录入 | 订单可见范围 | 操作日志 | 账号管理 | 系统设置 | 删除订单 |
| ---- | :---: | ---- | ---- | :---: | :---: | ---- |
| 系统管理员 | ✓ | 全部门店 | 所有门店 | ✓ | ✓ | 任意记录 |
| 门店管理员 | ✗（只查不拍） | 本门店 | 仅本门店 | ✗ | ✗ | ✗ |
| 拍照账号 | ✓ | 本人 + 同门店 | ✗ | ✗ | ✗ | 仅本人记录 |
| 查询账号 | ✗ | 本人 + 同门店 | ✗ | ✗ | ✗ | 仅本人记录 |

权限由角色固定派生，前端不提供单独勾选，因此不会出现「门店管理员可拍照」这类与角色矛盾的账号。门店与角色的分配仅系统管理员可操作，客户端只能只读查看自己的所属门店。

### 照片拍照时间水印

拍照时在照片**右上角烧录「年-月-日 时:分」水印**。水印写入照片本身（而非界面叠加），因此导出、打印后的照片同样带有收衣时间，可作为纠纷时的存证依据。字号按图像短边比例自动缩放，摄像头最大分辨率（如 4000×3000）下依然清晰可读；采用半透明深色底 + 白字，深浅色衣物背景下都能看清。连拍时每张记录各自的拍摄时间，不会共用同一时刻。

### 登录框记住账号与密码

登录页新增账号下拉，可选择本机保存过的账号（显示各自角色与所属门店，带 🔑 表示已保存密码），并可勾选「记住账号」「记住密码」。

安全设计：

- 密码经 Electron `safeStorage` **系统级凭据保护**（Windows DPAPI / macOS Keychain）加密后保存，磁盘上只有密文，**不明文落盘、不上传服务器**
- 系统凭据保护不可用时自动禁用「记住密码」并提示原因，**不会退化为明文保存**
- 默认只记住账号名，记住密码需显式勾选；界面对共用电脑场景给出风险提示
- 凭据读写走本地 IPC，不经客户端→服务端的远程转发通道
- 保存的凭据写入 `data/credentials.json`（已 gitignore），删除该文件即清除全部保存记录

### 服务端开机自动启动

系统设置新增「开机自动启动」开关（**仅服务端模式可开启**）。开启后登录 Windows 时自动启动并**静默驻留托盘**、不弹窗，持续为各客户端提供照片服务，避免门店断电重启后服务没起来。

- 软件为**单实例**运行：自启后再次双击图标不会启动第二个程序，而是唤起已在运行的窗口，避免两个进程争抢同一服务端口
- 本机从服务端切回客户端时会自动取消该设置，防止工位机变成开机常驻
- 若系统组策略禁止设置登录项，界面如实提示设置未生效，不会假装成功
- 开关与取消均记入操作日志（操作类型「开启开机自启」/「取消开机自启」）

### 订单数据保留期（超时自动删除）

系统设置新增「订单数据保留期」，超过保留天数的订单及其照片会被自动清理，用于控制长期累积占用的磁盘空间。

⚠️ **这是不可逆删除**，因此设有多道防误删保护：

- **默认关闭**：未设置保留期时，系统在任何情况下都不会自动删除数据
- **最小 1 天**：显式拒绝 0 与负数——「保留 0 天」等于清空全部订单
- **全删熔断**：若某次清理将删除**全部**订单（例如系统时钟异常跳到未来，导致所有订单都判定为超期），自动清理会**拒绝执行并告警**，而不是照删
- **仅服务端模式执行**，客户端模式下不会清理（数据以服务端为准）
- 界面提供「**试算**」：只统计不删除，让管理员在真删之前看到确切影响条数
- 保存设置不会立即删除；自动清理在启动后延迟执行一次，之后周期性检查
- 首次开启或缩短保留期时弹确认框提示影响面（延长或取消不弹）
- 每次自动清理记入操作日志（操作类型「自动清理过期订单」），写明清理条数与保留期限
- 仅**系统管理员**可设置；门店管理员与其他角色无此权限

### 内置操作手册

侧边栏「📖 操作手册」页（**所有角色可见**），章节按当前账号角色自动裁剪——拍照账号看不到「用户与权限」「系统设置」等章节，系统管理员可见全部（便于指导门店与排障）。左侧目录可点击跳转，手册随软件打包，**离线环境也可查阅**。

手册同步机制：`docs/manual.md` 是源文件，`npm run build` 前经 `prebuild` 钩子自动同步到 `renderer/assets/manual.md`（`docs/` 不在打包范围内，不同步则安装包里读不到）。同步脚本会校验：手册版本号与 `package.json` 一致、未使用渲染器不支持的语法、角色标记取值合法——任一不符即中断构建，避免发版时遗漏更新文档。

### 离线冗余（客户端灾难恢复）

服务器失联时客户端可**离线登录、拍照存档**，操作进入本地离线队列；服务器恢复上线后**自动回传同步**，界面顶部显示离线状态与同步进度，确保门店不停工。

### 批量删除

客户端「记录查询」与管理端「数据查看」页支持勾选多张卡片（或全选本页）后一键批量删除；客户端账号只能删除自己存档的记录，批量删除操作会写入日志。

### 按订单号批量下载照片

客户端「记录查询」与管理端「数据查看」页提供「按订单号批量下载」：勾选记录后导出勾选记录涉及的条码（订单号），未勾选则导出当前列表全部条码。选择保存目录后，照片按条码分文件夹保存，文件名为「拍摄时间_第N张.jpg」。服务端模式从本机照片目录复制；客户端模式自动从服务器逐张拉取保存到本机。导出统计（成功/缺失跳过/失败）会提示并写入操作日志；导出范围与查询可见范围一致（本人 + 同门店，系统管理员为全部）。

### 按日期导出照片

客户端支持按日期范围导出照片，自动按条码分文件夹归档，并附带一张归档表格。表格**按订单（条码）汇总**，每个条码一条记录，包含三列：条码、照片数量、归档文件夹位置——不逐张照片罗列，但照片本身仍全部导出到对应条码文件夹。服务端本地复制、客户端从服务器拉取，导出计入操作日志；门店管理员与查询账号的导出范围限本门店。

### 版本与更新

- 当前版本：**v1.1.4**，侧边栏底部也会显示；各版本变更内容见 `CHANGELOG.md`
- **更新分发（GitHub Releases）**：新版本安装包发布到项目的 GitHub Releases。应用启动或点击「检查更新」时自动检测，发现新版本后**自动弹出更新弹窗**，展示当前版本的更新内容；点击「**一键下载更新**」即可自动下载安装包到软件安装目录下的「软件更新」文件夹（实时进度、可取消），下载完成后自动打开文件夹定位文件，双击安装覆盖升级。管理端「系统设置 → 版本与更新」页同样提供一键下载
- **备用机制（更新文件夹）**：无法访问 GitHub 的环境（如纯内网门店）自动回退为原有机制——把带版本号的安装包放入服务端电脑的「软件更新」文件夹（软件安装目录下），各客户端/服务端启动时自动扫描并提示
- **强制推送**：管理端可开启强制推送并选择待推送安装包，客户端下次登录时自动检测并按提示安装
- 发布新版本流程：`npm run build` 打包 → 到 GitHub 仓库创建 Release（标签如 `v0.2.0`）→ 上传 `dist` 目录中的 `.exe` 安装包 → 各终端应用检查更新即可收到提示

> 注意：`main/main.js` 顶部的 `GITHUB_REPO` 与 `package.json` 中的 `repository` 字段需替换为实际的 GitHub 仓库地址。

## 五、数据存储位置

数据保存在服务端电脑的用户数据目录下：

```
%APPDATA%\星期衣精致洗衣衣物照片系统\

  ├── data\offline-queue.json 客户端离线待同步队列
  └── photos\                衣物照片（可在管理端「系统设置」中改到任意目录）
```

> **更新文件夹**：「软件更新」位于软件安装目录下（与程序文件同目录），更新下载、内网分发与强制推送共用；不再位于用户数据目录。

此外，**每台电脑各自**在本地保存登录凭据（不集中在服务端，也不随客户端上传）：

```
%APPDATA%\星期衣精致洗衣衣物照片系统\
  └── data\credentials.json  记住的账号与加密后的密码密文（safeStorage 系统级加密）
```

该文件删除后即清除本机保存的全部登录凭据；已加入 `.gitignore`，不会进入版本库。

## 七、验证命令

```bash
npm run verify    # 一次跑完全部 8 个校验脚本，共 384 项断言
```

也可单独运行任一脚本，例如：

```bash
node scripts/verify-store.js          # 数据层（门店可见性、四级角色、日志、导出）
node scripts/verify-credentials.js    # 凭据安全属性（密码不明文落盘等）
node scripts/verify-manual-render.js  # 手册渲染与角色裁剪
node scripts/verify-thumb.js          # 缩略图生成 / 缓存 / 清理与照片接口
```

打包前会自动执行 `prebuild`（复制 Vue 运行时 + 同步操作手册）。若手册版本号与
`package.json` 不一致，或手册使用了内置渲染器不支持的语法，构建会直接中断报错。

## 八、常见问题

**Q：客户端连不上服务器？**
A：绝大多数情况是服务端防火墙未放行端口，见「三、多电脑联网说明 → 同一局域网」的排查步骤；也可先在客户端启动设置页用「测试连接」定位问题。

**Q：扫码枪怎么用？**
A：扫码枪相当于键盘输入，光标停在「衣物条形码」输入框时扫码即可自动填入。

**Q：拍照有哪些快捷键？**
A：在拍照页，**空格键**拍摄一张（可连按多张连续拍摄），**回车键**把已拍的全部保存；光标在输入框内时快捷键不生效，避免误触。

**Q：修改端口/模式后要重启吗？**
A：端口修改会自动重启服务立即生效；切换运行模式（服务端↔客户端）需重启应用。

**Q：照片文件可以直接备份吗？**
A：可以。照片是独立的 JPG 文件，备份照片目录 + `data` 目录即完成全量备份。

**Q：服务器关了客户端还能用吗？**
A：可以。客户端支持离线模式，服务器失联时可离线登录和拍照存档，服务器恢复后自动同步。

**Q：激活码怎么获取？**
A：把登录页显示的本机机器码发给软件维护者/管理员，由其生成对应激活码。激活码计算工具（`scripts/license-tool.js`）含密钥与算法，**不随公开仓库分发**，需向维护者单独索取（见 v1.0.0 更新日志）。

**Q：服务端关闭窗口会断开客户端连接吗？**
A：不会。服务端模式关闭窗口只隐藏到系统托盘，HTTP 服务持续运行；托盘菜单提供「显示主窗口」和「退出程序」选项。只有点击「退出程序」才会真正停止服务。

**Q：为什么双击图标后没有打开新窗口？**
A：软件为单实例运行。若已在运行（包括开机自启后静默驻留托盘），再次启动会把已有窗口唤到前台，而不是新开一个进程——这是为了避免两个进程争抢同一服务端口。可先看系统托盘是否已有图标。

**Q：开机自启开了但重启后没生效？**
A：先确认本机是**服务端模式**（客户端模式下该开关会被禁用）；若被系统组策略限制，界面会如实提示设置未生效而不会显示「已开启」。可在「系统设置 → 开机自动启动」点「刷新状态」查看系统实际登记的值。

**Q：「记住密码」为什么是灰的？**
A：说明本机系统凭据保护（Windows DPAPI / macOS Keychain）不可用。此时软件只记住账号名，**不会以明文保存密码**——这是刻意的安全设计，不做明文降级。

**Q：换电脑/重装系统后记住的密码还能用吗？**
A：不能。保存的密码由系统级凭据保护加密，绑定当前操作系统账户，换机或重装后无法解密。软件会提示「已保存的密码无法解密，请手动输入」，重新登录并勾选记住即可。

**Q：店员看不到「用户与权限」等章节？**
A：内置操作手册按当前账号角色裁剪章节，这是预期行为。店员账号（拍照/查询）只看到与自身职责相关的内容；需要查看完整手册请用系统管理员账号登录。

**Q：登录后提示「账号已在其他设备登录」并被退回登录页？**
A：这是**唯一登录**机制：同一账号同一时间只能在一台电脑上登录，别处登录后本机会话立即失效。这不是密码错误，无需重置密码。提示中会写明顶下线的登录时间与来源 IP，可据此确认是谁在用该账号。若确实需要两台电脑同时使用，请由系统管理员为每台电脑建立独立账号（也便于日志追溯到人）。

**Q：离线期间收的衣物，账号在别处登录后数据会丢吗？**
A：不会。离线登录不经服务端签发会话，**不受唯一登录限制**；离线数据存在本机待同步队列中，只有服务器确认接收成功才会移除。重新登录后即会自动补传，即使该账号此时已在其他电脑登录。

**Q：提示「登录会话已在其他设备失效，请重新登录后再同步离线存档」？**
A：说明本机此前的登录已被顶下线，离线队列暂未补传。重新登录即可继续同步，**队列中的数据不会被清空**。
