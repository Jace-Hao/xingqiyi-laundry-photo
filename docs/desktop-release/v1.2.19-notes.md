# 桌面端 v1.2.19 发布说明

**一句话**：回滚自动曝光辅助引擎，改为用户**手动控制**的「摄像头亮度」滑块——相机原生 `brightness` 参数在 ISP 层压暗 / 提亮，实时预览所见即所得，按「全局默认 + 单设备覆盖」持久化；设备不支持时滑块自动禁用。

## 一、这个版本改了什么

### 1. 移除自动曝光辅助引擎（整套）

v1.2.18 里「亮度」只是自动曝光辅助的内部兜底档，由辅助引擎自动选用压暗。本版按产品决策**彻底移除整套自动曝光辅助子系统**（网格统计、滞回决策、闭环步进、幽灵能力检测、档位降级、软件兜底 LUT），改用用户**手动控制**的摄像头亮度滑块替代。

### 2. 确认移除「软件屏幕亮度调节」并无残留

v1.2.17 曾给预览 `<video>` 套 SVG `feComponentTransfer` 滤镜做后期压暗，在 Electron 下会导致整片白屏——该滤镜已于 v1.2.18 移除。本版复核确认：预览链路**没有任何后期滤镜、`styles.css` 无 `filter: brightness`、成片也不做任何亮度 LUT**，压暗一律走相机原生 `brightness`（ISP 层，预览与成片天然同源）。

### 3. 新增「摄像头亮度」手动滑块（取代自动曝光辅助）

- 通过 `track.applyConstraints({advanced:[{brightness}]})` 下发**相机原生亮度参数**，在 **ISP 层**压暗 / 提亮；
- **范围 / 默认 / 步进**取自 `getCapabilities().brightness.{min,max,step}`；默认取设备自身默认档位（`getSettings().brightness`），缺失时回退量程中点；
- **实时预览**：拖动即下发、所见即所得；`step>0` 时对齐步进网格，`step=0` 仅做量程钳位（连续亮度）；
- **持久化**：按「全局默认 + 单设备覆盖」保存（localStorage 注入回调，兼容旧数据：无键时回落默认），重启 / 换设备后自动恢复并下发；
- **降级**：设备不支持 `brightness` 能力时滑块**自动禁用并提示**，整条亮度逻辑 no-op，不影响正常拍摄。

---

## 二、升级注意事项

- 旧配置无亮度键时自动回落默认，不影响已存的用户数据与预约记录。
- 部分老旧 / 虚拟摄像头不支持 `brightness` 能力，届时滑块置灰并提示「当前摄像头不支持亮度调节」，属正常降级，画面仍可正常拍摄。
- 移除自动曝光辅助后，极端逆光 / 黑衣过曝等场景不再由软件自动补偿，需门店按需手动拉低亮度滑块。
