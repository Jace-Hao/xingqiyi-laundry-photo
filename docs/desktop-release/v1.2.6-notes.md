# 桌面端 v1.2.6 发布说明

**一句话**：本版修复了 v1.2.5 安装包「缺激活组件」的问题——v1.2.5 更新后登录页会报「激活组件不完整，无法验证授权」，导致无法正常进入。v1.2.6 让发布包始终携带完整的激活组件。

| 项目 | 值 |
|---|---|
| 版本 | v1.2.6 |
| 配套 | 移动端 **v1.1.0**（无需联动升级） |
| 上一版 | v1.2.5 |

---

## 一、本版修了什么

### 激活组件不完整（核心修复）

部分用户在更新到 v1.2.5 后，登录页直接提示：

> ⚠️ 激活组件不完整，无法验证授权：请重新安装完整安装包，或联系软件维护者

**根因**：激活/授权模块依赖 `main/license-secret.json`（含授权密钥），该文件按设计被 `.gitignore` 忽略、只随安装包分发，不进仓库。v1.2.5 的发布流水线在干净检出（不含此文件）后直接打包，导致产出的安装包里没有激活组件；`license.isSecretAvailable()` 返回 `false`，渲染层据此显示「激活组件不完整」。

**修复**：把授权密钥改为以 GitHub Actions Secret 的形式存储（名为 `LICENSE_SECRET`，用仓库 libsodium 公钥密封后入库，密钥原文不出现在任何日志或仓库中），并在发布工作流新增「注入授权密钥」步骤：

1. 构建前从 `Secrets.LICENSE_SECRET` 取出密钥，写入 `main/license-secret.json`；
2. 紧接着用 `license.isSecretAvailable()` 校验，校验不过则 `exit 1` 并给出明确报错，把「缺激活组件」挡在打包之前，而不是发出来才发现；
3. 后续 electron-builder 打包（`files` 含 `main/**`）就会把它带进安装包。

这样一来，无论谁触发发布，产出的安装包都自带完整激活组件，不会再出现 v1.2.5 那种「更新后无法登录」的情况。

## 二、兼容性

- **移动端保持 v1.1.0，不需要联动升级**：本版未改动任何对外 HTTP 接口与数据结构。
- **已装 v1.2.5 可直接覆盖升级**，配置与照片数据不丢失；升级后登录页不再提示「激活组件不完整」。
- **已装 v1.2.4 及以下版本**同样可直接覆盖安装到 v1.2.6。

---

## 三、管理员操作指南（验证与回滚）

### 上线后验证

1. 覆盖安装 `xingqiyi-laundry-photo-setup-1.2.6.exe`；
2. 启动后在登录页确认**不再**出现「激活组件不完整」提示，可正常进入；
3. 若仍提示该错误，说明发布流水线未正确注入密钥（构建日志会有 `::error::未配置 Secrets.LICENSE_SECRET` 或 `授权密钥注入后校验失败`），请联系维护者核对该 Secret 是否就位，必要时重新触发发布。

### 回滚

若发现异常（如仍无法激活、启动即崩溃、或非激活功能受影响），直接覆盖安装上一稳定版 `xingqiyi-laundry-photo-setup-1.2.5.exe` 即可。**必须整包覆盖安装，不要只替换单个文件**。

## 四、安装

双击 `xingqiyi-laundry-photo-setup-1.2.6.exe`，按向导完成安装（可自选目录）。安装包内置全部运行环境，目标电脑无需安装 Node.js。

安装包 SHA-256 校验值见发布附件 `SHA256SUMS.txt`。
