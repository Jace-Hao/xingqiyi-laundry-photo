# 桌面端 v1.2.14 发布说明

**一句话**：修 v1.2.13 之后出现的两个新问题——画面**每隔几秒就亮一下又暗回去**（循环跳亮度），以及**整体偏暗、黑裤和垫板一起发黑**。现在压暗会稳定保持，徽标显示的数字也与实际一致。

| 项目 | 值 |
|---|---|
| 版本 | v1.2.14 |
| 配套 | 移动端 **v1.1.0**（无需联动升级） |
| 上一版 | v1.2.13 |
| 建议 | 已升到 v1.2.13 的门店**全部升级**（v1.2.13 的曝光辅助会来回跳变） |

---

## 一、这个版本解决了什么问题

v1.2.13 让曝光补偿真正生效了，但门店随后反馈两个新现象：

1. **画面循环跳亮度**：黑色衣物放上垫板后，画面暗几秒、亮几秒，来回反复，停不下来；
2. **整体过暗**：连黄色垫板都跟着变黑，黑裤几乎没有纹理，徽标一度显示「-5.0 EV」。

### 为什么 v1.2.13 会这样

原因有点反直觉：**是曝光辅助自己把「黑色衣物还在不在」的判断给弄失效了**。

曝光补偿压暗的是**整个画面**——不只是衣物，**亮黄色的垫板也跟着变暗**。而程序判断「衣物还在不在」靠的是「画面里有没有一块足够亮的垫板作参照」。垫板被压暗后掉出了参照标准，程序就以为「垫板不见了 / 画面全是黑的」，判定衣物已经被拿走，于是把亮度恢复回去；亮度一恢复，垫板又够亮了，程序又认为衣物回来了，重新压暗——如此循环。

打个比方：这就像一个人一边给镜头戴墨镜，一边靠墨镜里的亮度判断该不该摘墨镜，戴上看不清就摘，摘了看清又戴上。

### 过暗又是另一回事

手动曝光档原本假设「我请求压 3 档，设备就压 3 档」。但这台设备实际执行得**比请求的更狠**（实际压了 5 档）。程序看到「太暗了」就往回调一点，调回来又太亮，再压下去又撞回深处——于是亮度在过暗与过亮之间来回打摆，徽标也显示出一个我们根本没请求过的 -5.0EV。

---

## 二、方案

### 1. 判断「衣物在不在」时，先把亮度还原回压暗前的尺度

介入期间，程序会把参与判断的亮度按「介入时垫板有多亮 / 现在垫板有多亮」这个**实测比例**还原回去——相当于先用一把随画面缩放的尺子量，再用固定标准判断。垫板被还原成压暗前的亮度，黑衣物也被还原成它本来的亮度，判定于是稳定下来，不再误判「衣物已拿走」。

- 闭环控制本身仍然看**真实画面亮度**（该压多少还是看实际效果，不弄虚作假）；
- 衣物**真的拿走后照样能正常退出**并恢复曝光，这条路径没有被改动。

### 2. 设备压得比请求更狠？那就别再往深处请求

每一步压暗之后，程序都会用实测亮度反推「设备**实际**执行了多少 EV」。一旦连续两次确认设备执行得比请求更深，就把请求下限收紧到设备**真正能到的深度**——反正请求更深也只会被设备压得更深，不如不请求。

- 日志新增 `CAM_EXP_OVERPRESS`，现场可直接看到：请求了多少、实际执行了多少、过压多深、下限被收紧到多少；
- **徽标改为显示实际生效的 EV**，不再显示那个「请求了但设备没照做」的数字。

---

## 三、门店需要做什么

**不需要任何操作**，覆盖安装即可。重点验收：

1. **黑色衣物放上垫板** → 约 4 秒后画面变暗，然后**稳定保持**，不再几秒一亮地来回跳；
2. **黑裤/黑衣应有纹理**（不是一片死黑），**垫板仍是黄的**（不会跟着发黑）；
3. 把衣物**拿走** → 约 3 秒后画面恢复正常亮度；
4. **白色鞋底/浅色部位**应能看出细节，不过曝；
5. **浅色衣物** → 不出现曝光徽标；
6. **用手捂住镜头** → 仍然提示「画面异常（全黑）」且拍不了。

若仍看到来回跳变，请把 `CAM_*` 日志导给我们——`CAM_EXP_OVERPRESS` 会直接告诉我们这台设备过压多深，`CAM_EXP_RELEASE` 的 `reason` 会告诉我们它是「真离场」还是「误判」。

---

## 四、排查用日志

| 日志事件 | 含义 | 怎么判 |
|---|---|---|
| `CAM_EXP_OVERPRESS` | 设备实际压得比请求更深 | 看 `requestedEv` / `measuredEv` / `overPress` / `evFloor`；出现即说明该设备已被识别并钳制 |
| `CAM_EXP_RELEASE` | 衣物移出，恢复曝光 | `reason` 为 `no-hit` 且在衣物仍在画面时出现，才是异常 |
| `CAM_EXP_STEP` | 每步曝光调整 | 看 `ev` 变化后 `subjectMean` 是否平稳收敛，不再来回摆 |
| `CAM_EXP_FALLBACK` | 降级 | `reason` 见 v1.2.13 说明（`comp-ineffective` / `manual-ineffective` / `ghost-remembered` 等） |
