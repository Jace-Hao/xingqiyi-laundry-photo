## 一、这个版本解决了什么问题

v1.2.15 之后，门店反馈：压暗确实发生了，但**预览窗口一点没变（仍很亮）**，拍出来的照片被调暗了，**可黑色皮衣的细节还是看不出**。

顺着现场日志和像素测量挖到根因（完整调查报告见 `docs/field-2026-10-23-tier0-darkening.md`）：

### 根因 1：闭环目标 `expTargetMean=58` 在该设备上过暗（标定问题，不是机制 bug）

那台设备的 ISP 会把黑色衣物（反射率约 5%）**提亮约 3EV**——黑色皮衣在传感器里读到均值约 148，而闭环目标是 58。按 58 为目标要压到深暗带，把深色、低对比的皮衣纹理一起抹平了。LUT 数学是对的，是目标值定低了。

**现在**：现场把 `expTargetMean` 从 **58 重新标定为 105**——同设备 LUT 对照显示，ev=-1.5（主体 98）时皮衣褶皱/高光/口袋清晰可读；105 对均值 148 的主体只需压约 -1.1EV，落在验证过的可读区，深色而有纹理的皮衣细节回来了。

### 根因 2：tier0 软件兜底只压暗存档图、不压暗预览

tier0 软件兜底（设备不支持硬件补偿时）的 LUT 只作用在存档图上，预览画面不动。这造成「预览亮、照片暗」的结构性错位——用户看到的和最后成片对不上。

**现在**：预览画面同步压暗——给 `<video>` 元素加 `filter: brightness(2^(ev/γ))`，与存档 LUT **同源同系数**，所见即所得。预览和照片现在是一致的。

### 顺带修复：过压设备徽标不诚实

标定后还暴露一个真实 bug：过压设备（实际压得比请求更深）一步收敛进死区时，徽标上的实际生效 EV 没更新，停在 0.0EV，与「实际生效深度」对不上。现已修正——过压确认时据实记录实际生效 EV，徽标如实显示。

## 二、门店会观察到的变化

- 预览画面和存档照片**一致变暗**；黑色衣物（深色而有纹理）的细节在预览与存档里都看得见。
- 徽标如实显示实际生效的压暗 EV（过压设备不再停在 0.0EV）。
- 浅色衣物、正常设备：行为与 v1.2.15 一致，无感。
- 这一切都是自动的，**不需要任何操作**，覆盖安装即可。

重点验收（问题设备）：

1. 黑色衣物放上垫板 → 预览与照片**都变暗**，且皮衣褶皱/口袋等纹理可见；
2. 画面稳定、**不来回跳**，预览亮度与成片一致；
3. 把衣物拿走 → 约 3 秒后徽标消失、画面恢复正常；
4. 浅色衣物 → 不出现压暗；
5. 用手捂住镜头 → 仍然提示「画面异常（全黑）」且拍不了。

## 三、排查用日志

| 日志事件 / 字段 | 含义 | 怎么判 |
|---|---|---|
| `CAM_EXP_STEP` | 每步曝光调整 | 看 `ev` 与 `subjectMean` 是否平稳收敛到约 -1.1EV 附近（此前会一路压到 -2.9EV） |
| `CAM_EXP_OVERPRESS` | 设备实际压得比请求更深 | 本版本徽标据实显示其 `actualEv`，不再停在 0.0EV |
| `CAM_EXP_FALLBACK{reason:'frame-collapse'}` | 检出画面崩塌，已还原并降软件压暗 | 见 v1.2.15 说明 |
| `CAM_EXP_RELEASE` 的 `gate` / `rawMean` / `adjusts` / `ghostStrike` | 退出时的闸门明细 | 见 v1.2.15 说明 |

若仍有异常，请把 `CAM_*` 日志导给我们。
