## 一、这个版本解决了什么问题

v1.2.16 把闭环目标重新标定到 105、并让预览跟着一起压暗后，门店在问题设备上仍反馈：**照片整帧像蒙了一层灰，白色垫板不再白，黑色衣物也看不出层次**。

顺着像素测量挖到根因（完整调查报告见 `docs/field-2026-10-23-tier0-darkening.md` §7 二次修复段）：

### 根因：tier0 软件兜底的 LUT 是「均匀线性乘法」，把高光也一起压没了

v1.2.16 的软件压暗用 `out = in × 2^(ev/γ)`（γ=2.2）——这是一条**整帧均匀乘法**。问题设备上白色垫板在传感器里已经是削顶的 255，均匀乘以 0.75 之类系数后，整片 255 被压成一片均匀的灰平台（约 192）。白板没了白度、黑色衣物没了暗部层次，**整帧看起来就是蒙灰**，和「调亮度」的预期完全相反。

**现在**：tier0 软件兜底改成**保高光色调曲线**——

- 中间调 / 暗部仍走 `in × 2^(ev/γ)`，把过曝的主体压回可读区；
- 码值 ≥ `whiteStart`(200) 的**已削顶高光**改走线性肩线，平滑压到 `whiteOut`(238)，不再一路压成灰平台。

白板仍白（255→238，保留高光白度）、黑衣暗部仍被压回有层次的暗调，整帧不再发灰。

### 顺带修正：预览与成片真正同源

v1.2.16 的预览用 CSS `brightness()`，本质还是均匀乘法，和存档 LUT 不是同一条曲线。现改为 SVG `feComponentTransfer` 滤镜（`#xqy-exposure-lut`，`color-interpolation-filters="sRGB"`），`tableValues` **直接消费 `buildExposureLut` 算出的 256 项曲线**——预览和存档图逐点一致，所见即所得。

### 为什么不做「硬件调亮度」（方向 A）

现场在问题设备 HB-HD Camera **eba4:dc26** 上验证过：它的 `exposureCompensation.min ≥ 0`（只能提亮，负 ev 被钳回 0，是幽灵能力形态），因此不入选硬件补偿档（tier1）；切 `exposureMode:'manual'`（tier2）又会触发画面崩塌，被崩塌守卫直接降回软件兜底（tier0）。**对该设备，硬件调亮度没有可行路径**。本次只做软件后处理的保高光修复，这是该设备上唯一能落地的正确方向。

## 二、门店会观察到的变化

- 白色 / 浅色衣物放上垫板 → 预览与照片**白板仍白，不再发灰**；
- 黑色衣物 → 预览与照片**变暗且纹理层次可见**（暗部有层次，不是一片死黑）；
- 预览亮度与成片**完全一致**（同源 LUT）；
- 浅色衣物、正常设备：行为与 v1.2.16 一致，无感；
- 这一切都是自动的，**不需要任何操作**，覆盖安装即可。

重点验收（问题设备）：

1. 白色垫板 / 浅色衣物放上 → 预览与照片**白板仍是白，不蒙灰**；
2. 黑色皮衣放上 → 预览与照片**变暗且褶皱/口袋纹理可见**；
3. 画面稳定、**不来回跳**，预览亮度与成片一致；
4. 把衣物拿走 → 约 3 秒后徽标消失、画面恢复正常；
5. 用手捂住镜头 → 仍然提示「画面异常（全黑）」且拍不了。

## 三、排查用日志

| 日志事件 / 字段 | 含义 | 怎么判 |
|---|---|---|
| `CAM_EXP_STEP` | 每步曝光调整 | 看 `ev` 与 `subjectMean` 是否平稳收敛；白板样本的高光码值应停在 `whiteOut`(238) 附近而非被压成灰平台 |
| `CAM_EXP_OVERPRESS` | 设备实际压得比请求更深 | 徽标据实显示其 `actualEv` |
| `CAM_EXP_FALLBACK{reason:'frame-collapse'}` | 检出画面崩塌，已还原并降软件压暗 | 见 v1.2.15 说明（本设备若走硬件档会触发） |
| `CAM_EXP_RELEASE` 的 `gate` / `rawMean` / `adjusts` / `ghostStrike` | 退出时的闸门明细 | 见 v1.2.15 说明 |

若仍有异常，请把 `CAM_*` 日志导给我们。
