# 桌面端 v1.2.3 发布说明

## 版本链更正：1.3.0 → 1.2.3

桌面端的版本线一直是 **1.2.x**（上一正式版 v1.2.2）。本版内容此前误编为 `v1.3.0`
发布，现更正为 **v1.2.3**，此后依次 1.2.4、1.2.5……

同时**移动端已拆分为独立仓库**，两端不再共用版本号，发布链路也彻底分开：

| 项目 | 仓库 | 版本来源 | 当前版本 |
|---|---|---|---|
| **桌面端** | `Jace-Hao/xingqiyi-laundry-photo` | `package.json` → `version` | **1.2.3** |
| 移动端 Android | `Jace-Hao/xingqiyi-laundry-photo-android` | `app/build.gradle.kts` → `versionName` | 1.0.0（重新计数） |

### 为什么要拆

两端共库同号时，桌面端的更新检查按「tag 数字最大」选版、**不区分产物类型**：
移动端发 v1.3.1 后，桌面端把它判成新版本，并把 Release 里的 **APK 当成安装包**
推给电脑用户（选版逻辑里有一句「取不到 .exe 就回退到第一个附件」）。
现在：

- 移动端产物只发布到移动端仓库，桌面端扫不到；
- 桌面端选版新增两道过滤：**tag 必须是纯版本号** + **必须带 `.exe`/`.msi` 安装包**，
  并删掉了「回退到第一个附件」的兜底；
- 仓库内新增 `scripts/verify-release-isolation.js` 持续守住这条边界
  （已并入 `npm run verify`）。

## 本版功能（即原 v1.3.0 的内容）

### 新增

- **服务端能力集接口 `system/capabilities`**，`/ping` 同步返回能力集。移动端配置
  服务器地址时先 `GET /ping`，即可拿到 `apiVersion` / `serverVersion` / `features`，
  无需登录就能判断服务端是否支持原始上传等增量功能，从而对旧服务端正确降级。
- **原始二进制照片上传 `POST /upload`**（配 `records/addByFile` 建档）。base64 上传
  体积膨胀约 33% 且需整体读入内存，弱网中断即从零重传；改为「先暂存原始字节、
  再凭文件名建档」两步。暂存文件名由服务端随机生成（客户端文件名不可信），
  `_upload/<日期>/` 下的残留由 `purgeStagedUploads` 定期清理。
- **备注订正 `records/setNote`**：事后修改已存档记录的备注。
- **`/photo` 支持 `?w=` 缩略图**，并兼容用查询参数传递连接码。

### 修复

- 移动端「测试连接」在旧版桌面端下误报「不是本系统的数据」（三个缺陷叠加）：
  ① Gson + Kotlin 非空类型陷阱；② 端口提示误报；③ 探活指纹校验短路放行。
  详见 CHANGELOG。

## 兼容性

- 移动端 **v1.0.0 及以上**要求桌面端 ≥ **v1.2.3**。低于该版本时连接仍可用，
  但会提示「服务端版本较旧，原始上传与改备注不可用」，自动降级为 base64 上传。
- 桌面端低版本不受影响，可继续正常使用。

## 安装

双击 `xingqiyi-laundry-photo-setup-1.2.3.exe`，按向导完成安装（可自选目录）。
安装包内置全部运行环境，目标电脑无需安装 Node.js。

- 已安装旧版本可直接覆盖升级，配置与数据不丢失。
- 若曾安装过误编号的 1.3.0：其版本号大于 1.2.3，**不会**收到本次更新提示，
  但两者内容一致，无需任何操作；后续 1.2.4 起会正常提示。
