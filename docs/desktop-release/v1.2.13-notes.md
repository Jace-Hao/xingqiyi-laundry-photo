# 桌面端 v1.2.13 发布说明

**一句话**：本版修的是「徽标说在压暗、画面一点没变」——部分摄像头嘴上支持曝光补偿、实际完全不生效，v1.2.12 会被它一直骗下去。现在程序会**实测压暗是否真的起作用**，骗人的档位自动跳过后改用真正有效的路径；同时修掉了软件兜底路径把照片压得过黑、白色细节全丢的问题。

| 项目 | 值 |
|---|---|
| 版本 | v1.2.13 |
| 配套 | 移动端 **v1.1.0**（无需联动升级） |
| 上一版 | v1.2.12 |
| 建议 | **强烈建议 v1.2.12 门店全部升级**（v1.2.12 的曝光辅助在部分机型上等于没生效） |

---

## 一、这个版本解决了什么问题

v1.2.12 上线后门店反馈：**徽标显示「曝光补偿 -2 EV」，但画面亮度纹丝不动，白色鞋底依旧一片死白、没有细节。**

排查日志发现：某型号摄像头的补偿档位确实一路推到了 -2.0 EV，但画面实测亮度始终停在 155～182，**一步都没降**。这类摄像头属于「**幽灵能力**」——系统接口里它明确上报了 `exposureCompensation` 的取值范围，下发负补偿也不报错，但图像亮度完全不受它控制。

v1.2.12 只判断「接口说支持、下发没报错」，就认为补偿成功了，于是会一直停在这个无效档位上，既压不暗，又挡住了其它真正有效的压暗手段。

### 同时修掉的第二个问题（白色看不到细节）

当摄像头连硬件补偿都不可用时，v1.2.12 会走「拍照瞬间做软件压暗」的兜底。这条路径的压暗量**算错了**：

- 它按线性光的方式算压暗，但图像是 sRGB 编码值，两者不是同一套刻度，结果 -3 EV 实际压出了约 -12 EV；
- 一张亮度 150 的存档图被压到 **4**（几乎纯黑，本该是 58）；
- 而已经过曝的纯白 255 **压完还是 255**——高光一个没救回来，正是「白色看不到细节」的直接原因。

---

## 二、方案

### 1. 压暗之后要「回头看效果」，骗人的档位自动跳过

每施加一次曝光调整，程序都会在约 0.6 秒后**重新采样画面实测亮度**，和 sRGB 模型算出的理论压暗量对比：

| 实测结果 | 判定 | 动作 |
|---|---|---|
| 亮度确实降到了理论值的附近 | 能力**有效** | 继续用，正常闭环 |
| 亮度几乎没动 | **幽灵能力** | 立刻放弃该档位，降级到下一档，并把这台设备记进「无效名单」 |

**记进名单的意义**：同一台设备后续每件衣物都**直接跳过**这个无效档位，不再让门店反复看「徽标说在压暗、画面没变」。无效窗口从「每件衣物都要重新试一遍」降到 **0**。

判定所需的时间：从识别到黑色衣物算起，约 **4 秒内**自动落到真正能压暗的路径上。

### 2. 软件兜底的压暗量按 sRGB 编码值重算

改用与图像编码一致的刻度计算：目标亮度 58 时，亮度 150 的像素压到 **58**（层次保留），过曝的纯白 255 压到 **99**（高光拉回可辨范围），原本就很暗的暗部（20/30/45）压到 8/12/17，不会糊成一片纯黑。

### 3. 软件兜底不再「一路压到底」

v1.2.12 的软件压暗缺少反馈，会一路推到 -3 EV，比实际需要多压约 1.27 档，照片整体偏黑。现在改为**按目标亮度一次算准**需要压多少，不再逐步试探。

### 4. 「无效名单」按设备记，不串档

名单按摄像头设备标识分别记录，换摄像头即失效，不会因为换了一台好设备而把它一起挡在硬件补偿之外。

## 三、门店需要做什么

**不需要任何操作**，覆盖安装即可。

如果门店此前反馈过「徽标有、画面不变」，升级后请重点复核：

1. 拍**黑色衣物**：约 4 秒内画面应**真的变暗**，不再停在原来的亮度；
2. 拍**白色鞋底 / 白色衣物**：过曝的白色区域应能看出纹理，而不是一片死白；
3. 拍**浅色衣物**：不应出现曝光徽标（曝光辅助不介入）；
4. **用手捂住镜头** → 必须仍然提示「画面异常（全黑）」且拍不了（验证安全拦截没被削弱）。

若升级后仍是「徽标在、画面不变」，请把 `CAM_*` 日志导出给我们——这类日志能直接告诉我们设备是不是幽灵能力、降级到了哪一档。

## 四、排查用日志

| 日志事件 | 含义 | 怎么判 |
|---|---|---|
| `CAM_EXP_ENGAGE` | 识别到黑色衣物，开始压暗 | 看 `tier`：1 = 硬件负补偿，2 = 手动曝光，**0 = 软件压暗** |
| `CAM_EXP_STEP` | 每步曝光调整 | 关键：看 `ev` 变化后 `subjectMean` **有没有跟着降**；不降即幽灵能力 |
| `CAM_EXP_FALLBACK` | 降级 | 现场看到这条即说明已自动切换路径，属**预期行为**，看 `reason` 区分原因 |
| `CAM_EXP_RELEASE` | 衣物移出，恢复曝光 | 正常 |
| `CAM_EXP_BLACKGATE` | 曝光辅助生效期间的正常拍摄放行 | 正常，说明没有把黑色衣物误判成「镜头被挡」 |

`CAM_EXP_FALLBACK` 的 `reason` 取值：

| reason | 含义 |
|---|---|
| `comp-ineffective` | 硬件负补偿**实测无效**（幽灵能力），已降级 |
| `manual-ineffective` | 手动曝光**实测无效**，已降到软件压暗 |
| `ghost-remembered` | 命中无效名单，**直接跳过**该档位，不再重走无效窗口 |
| `software-fallback` | 设备本就不支持任何曝光能力，走软件压暗 |
| `no-track-capability` / `cycle-error` / `fail-limit` / `engage-apply-failed` / `demote-apply-failed` | 取不到能力、异常、连续失败等其它降级原因 |

第二件及以后的衣物若出现 `ghost-remembered`，说明名单已生效，无需再试无效档位。

现场可用 `snapshot()` 的 `exposure` 字段查看当前状态（`state` / `ev` / `tier`）。若确认是曝光辅助导致异常，可临时在控制台执行 `window.__xqyExposureAssist = false` 关闭（仅当次会话生效）。
