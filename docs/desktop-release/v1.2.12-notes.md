# 桌面端 v1.2.12 发布说明

**一句话**：本版是**黑色衣物拍摄质量版**——拍摄黑色衣物时，摄像头自动曝光会把黑色提亮成灰白、衣物失去层次；现在程序会**自动识别画面里的黑色衣物**并临时压暗曝光，衣物拿走后**自动恢复**，黑色重新变回黑色。

| 项目 | 值 |
|---|---|
| 版本 | v1.2.12 |
| 配套 | 移动端 **v1.1.0**（无需联动升级） |
| 上一版 | v1.2.11 |

---

## 一、这个版本解决了什么问题

门店反馈：给**深色衣物**拍照时，照片里的黑色发灰、发白，褶皱和纹理都被冲淡了，看不出原本的颜色和质感；浅色衣物却一切正常。

原因是摄像头自身的**自动曝光**机制：画面里一旦大面积出现深色，摄像头的自动算法会「觉得太暗」而主动提亮，结果黑色被抬成了灰色。这在手机拍照里也常见，但对洗衣留档照片来说是致命的——黑色的层次就是这类衣物唯一的信息量。

程序此前**完全依赖摄像头的自动曝光**，没有任何干预手段。

---

## 二、方案：识别到黑色衣物就临时接管曝光

新增「曝光辅助」能力，全程自动，门店无需操作：

### 1. 自动识别画面里的黑色衣物

对取景画面做低开销的网格化统计（每秒 4 次），判断是否存在「大片深色主体放在明亮台垫上」。为避免误判，设置了四道闸门：

| 闸门 | 排除的场景 |
|---|---|
| 场景整体亮度足够 | 门店灯光昏暗、或镜头被捂住 |
| 画面里存在明亮参照 | 没有亮台垫，无法区分「黑」与「暗」 |
| 深色区域面积适中 | 桌沿阴影、黑色电线等零星暗物 |
| 深色主体位于画面中央 | 边缘的无关暗物 |

因此**深蓝、深棕、深绿**衣物不会被误判（它们不会过曝发灰），**白色衣物**也不会。

### 2. 识别后动态压暗，拿走后自动恢复

- 命中后按画面实测亮度**逐步**施加负曝光补偿（每次不超过 1/3 档），约 3 秒平稳过渡，不会突然明暗跳变；
- 衣物移出画面约 2.5 秒后自动把曝光**归零并交还**摄像头自动控制；
- 期间界面会显示「曝光补偿 -x EV」的**小徽标**，一眼可知当前状态；
- 休眠、切换摄像头、关闭程序时都会把曝光还原，不会留下变暗的状态。

### 3. 摄像头型号不支持时自动降级

不同摄像头能力差异很大。程序会逐级尝试：优先用硬件负补偿 → 其次切换到手动曝光压低曝光时间 → 都不支持时改为**拍照瞬间做软件压暗**（保住暗部层次，而不是简单把整张图压黑）。此时徽标会如实显示「软件压暗」。

**全程不影响既有的清晰度 / 分辨率锁定**，也不干扰 v1.2.11 修好的拍照稳定性。

## 三、门店需要做什么

**不需要任何操作**，覆盖安装即可。建议做一次快速验收：

1. **黑色 T 恤 / 黑色羽绒服**放上亮色台垫 → 约 3 秒后出现「曝光补偿」徽标，照片里的黑色应明显变深、有质感；
2. 把衣物**拿走** → 约 3 秒后徽标消失，画面恢复正常亮度；
3. **白色 / 浅色衣物** → 不应出现徽标（曝光辅助不介入）；
4. **用手捂住镜头** → 必须仍然提示「画面异常（全黑）」且拍不了（验证安全拦截没被削弱）；
5. 连续拍 10 张不卡顿，切换摄像头、空闲休眠后唤醒拍摄均正常。

若门店的台垫不是亮色（例如米色、浅灰），黑色衣物可能不会触发——这是由于缺少「明亮参照」，属于预期行为，如需支持请告知我们调整。

## 四、排查用日志

| 日志事件 | 含义 | 怎么判 |
|---|---|---|
| `CAM_EXP_ENGAGE` | 识别到黑色衣物，开始压暗 | 正常，`tier` 为 1 或 2 表示走了硬件档 |
| `CAM_EXP_STEP` | 每步曝光调整 | 看 `ev`（累计档位）与 `subjectMean`（实测亮度）是否向目标收敛 |
| `CAM_EXP_RELEASE` | 衣物移出，恢复曝光 | 正常 |
| `CAM_EXP_FALLBACK` | 硬件曝光不可用，降级 | `tier: 0` 表示走了软件压暗，功能降级但可用 |
| `CAM_EXP_BLACKGATE` | 曝光辅助生效期间的正常拍摄放行 | 正常，说明没有把黑色衣物误判成「镜头被挡」 |

现场可用 `snapshot()` 的 `exposure` 字段快速查看当前状态（`state` / `ev` / `tier`）。若确认是曝光辅助导致异常，可临时在控制台执行 `window.__xqyExposureAssist = false` 关闭（仅当次会话生效），并请把 `CAM_*` 日志导出给我们定位。
