## v1.3.0（2026-10-02）

本版包含 **Android 移动端**（首版）与配套的桌面端服务端升级。

### 安装包

| 文件 | 平台 | 说明 |
|---|---|---|
| `xingqiyi-laundry-photo-setup-1.3.0.exe` | Windows x64 | 桌面端，NSIS 安装向导 |
| `星期衣衣物照片-v1.3.0-release.apk` | Android | 移动端正式签名包（minSdk 26 / target 34） |
| `星期衣衣物照片-v1.3.0-debug.apk` | Android | 调试包，包名带 `.debug`，可与正式版共存 |

**升级顺序：先装桌面端，再装移动端。** 移动端 v1.3.0 依赖桌面端新增的三个接口，若桌面端仍是旧版本，移动端会提示「服务端版本较旧，原始上传与改备注不可用」（连接本身不受影响，可正常登录拍照）。

桌面端与移动端均可覆盖安装，**数据与账号不丢失**。

### 新增

- **服务端能力集接口 `system/capabilities`**，且 `/ping` 同步返回能力集。移动端配置服务器地址时先探活，既能验连通性也能拿到 `apiVersion` / `serverVersion` / `features`，无需登录即可判断服务端是否支持新功能，从而对旧服务端正确降级而非直接判定连接失败。
- **原始二进制照片上传**（`POST /upload` + `records/addByFile`）。base64 上传体积膨胀约 33% 且需整体读入内存，弱网下中断即从零重传；改为「先暂存原始字节、再凭文件名建档」两步，服务端可按 Content-Length 直接落盘。上传文件名由服务端随机生成（客户端文件名不可信，避免路径穿越），中断残留由 `purgeStagedUploads` 定期清理。
- **备注订正 `records/setNote`**，可事后修改已存档记录的备注。
- **照片缩略图**：`/photo` 支持 `?w=` 参数，并兼容用查询参数传递连接码（移动端图片加载器无法附加自定义请求头）。

### 修复

- **安卓端「测试连接」在新旧版本桌面端混用时误报「对方返回的不是本系统的数据」**。现场地址与端口都填得完全正确（`http://192.168.110.10:17521`）却始终连不上，实为三个独立缺陷叠加：

  1. **Gson + Kotlin 非空类型陷阱（主因）**。旧版桌面端 `/ping` 只返回 `{"ok":true,"data":{"app":"xingqiyi"}}`，不含 `apiVersion` / `serverVersion` / `features`。而客户端把这些字段声明为非空 `String` 并给了默认值——编译器完全放行，但 Gson 反序列化不走主构造函数、不执行默认值兜底，缺失字段一律填 `null`，于是判空调用直接抛 NPE，被翻译成「对方返回的不是本系统的数据」，把**版本不兼容**伪装成**用户地址填错**，导致反复检查防火墙与 IP 而查不到真因。现已改为字段可空 + 计算属性兜底，旧版桌面端可正常连接并按最低能力集降级运行。
  2. **端口提示误报**。错误文案先把地址的 `://` 剥掉，随后又在已剥离的串里找一次 `://`，结果恒为空——导致**无论有没有填端口都提示「当前未指定端口，实际访问的是 80 端口」**，正是用户看到「已连接到 192.168.110.10:17521，但……实际访问的是 80 端口」这句自相矛盾提示的来源。现已改为统一解析地址，并在提示中附带**对方实际返回的内容片段**（脱敏后截断），让「连错服务」「版本过旧」一眼可辨。
  3. **探活指纹校验短路放行**。原判定在 `app` 字段缺失时会短路为「通过」——**最该拒绝的情况反而被放行**：任何返回 `{"ok":true,"data":{...}}` 的其他后端都会让用户看到「连接成功」，直到登录或上传才失败、且已离开现场无从排查。现已改为只要不是本系统一律拒绝。

- 更正上一版（`769ef8f`）将该故障根因误判为「用户漏写端口冒号」。当时新增的地址自动补端口逻辑本身有效，予以保留。

### 改进

- 连接到低版本桌面端时，「测试连接」会明确提示「服务端版本较旧，建议升级桌面端到 v1.3.0」，不再让功能静默消失后被当成缺陷。
- 排障提示附带对方实际返回的响应体片段，并对连接码、会话令牌等敏感字段脱敏后截断至 120 字符，可安全展示给用户与客服。
